# How it works

The internals behind the [README](../README.md): what moves where in a switch, what the mod does, and the files involved.

- **The app's account is its claude.ai sign-in**, the `Cookies` file in its one profile folder (`~/Library/Application Support/Claude`). Accounts not in use have their sign-ins parked in `~/.claude/desktop-account-switcher/park/<accountUuid>/`. A switch closes Claude, moves the sign-ins, and opens Claude again; the app then makes its own Code tab token for that account. The sign-ins are moved, never read. The one token the relay uses is a terminal login's access token, to ask Anthropic for that account's usage (`relay.sh usage`): it goes to `curl` on stdin, never on a command line, in a log or on screen. The research behind this is in [how-the-desktop-app-signs-in.md](how-the-desktop-app-signs-in.md).
- **The app's files are checked before Claude is closed.** None of these files are a public interface; an app update could move them. Before any switch or sign-in, the relay checks that `config.json` names the signed-in account (`lastKnownAccountUuid`), that `Cookies` is the app's cookie database, and that the session folders are there. Being signed out passes: the signed-out `Cookies` is parked like any other, and counts as not signed in. If not, it doesn't close Claude, and `relay.sh doctor` says what's missing. The Claude Desktop versions checked by hand are listed in `TESTED_VERSIONS` at the top of `relay.sh`; doctor flags any other version.
- **New accounts are learnt from the app.** `relay.sh add <name>` opens Claude signed out. Whatever account other than the current one you sign in to is added as `<name>`: its `accountUuid` from the app's `config.json`, its `orgUuid` from the session folder the app makes for it (`claude-code-sessions/<account>/<org>/`). If there are several, it takes the only one no other account has. `add` takes only a name that isn't in `accounts.json` yet, and never changes an existing entry's `accountUuid`; signing in to an account already there keeps it under its own name. `relay.sh signin <name>` is the same round trip for an account already added, to sign it in again.
- **One session list.** The app keeps sessions under `claude-code-sessions/<account>/<org>/` (and `local-agent-mode-sessions/…` for Cowork). Every account/org pair is a link to one shared folder, so every account sees the same sessions. Session files hold no account fields. The first time there are two accounts, the first account's folder becomes the shared one. When the app makes a real folder for an account in `accounts.json` (a new account's first sign-in), the next sign-in, switch or restart backs it up, moves its sessions into the shared folder, keeps the emptied folder as `<org>.merged-<time>`, and links it.
- **Per-account settings follow you.** A few app preferences are stored per account (keys holding the account or org id in `claude_desktop_config.json`), and Remote Control's on/off in `remote-control-state.json`. While Claude is closed for a switch, the relay copies the outgoing account's onto the incoming one.
- **Scratch paths are kept inside the app's folder.** The app files a session under Scratch only if its folder is inside its own `scratch-workspaces`, and on launch it deletes scratch folders no session names by exact path. While Claude is closed, the relay points any session using another profile folder's path back inside it.
- **The mod** (`mod/`, installed as `desktop-account-switcher@desktop-account-switcher-local`) runs in every Code tab session in the desktop app:
  - It records which sessions are mid-turn (a file per session in `busy/`, deleted when the turn ends, however it ends, when the session ends, and when it starts again). The relay clears `busy/` whenever it has closed Claude, since no turn outlives it.
  - When a turn fails with `rate_limit` while a usage window is at 95% or more (or the error says a limit was reached) and auto-switch is on (with no 5-hour or weekly window that full, it asks Anthropic first whether the model's own weekly limit is; the switch then cools the account down until that limit resets), it writes a hand-off listing the sessions to reopen and starts the relay. If the relay doesn't switch after all (it can't start, no other account has usage, or the new sign-in doesn't come up), those entries are dropped.
  - In a session the relay reopened, it sends one message saying why (a usage limit, a switch by hand, a restart, a sign-in, or being cut off mid-turn) and to carry on. It acts only when the session starts by being reopened (not on a compact or clear), only if the relay closed Claude after the entry was written (`closedAt`, stamped as it quits Claude), and only within 15 minutes, and only if the entry's `account` (the account Claude was to come back on) is the session's own; older entries are dropped. After a switch to another account (not a restart or sign-in), the message also lists the artifacts the session published before (each publish shows in its transcript as `Published <file> at <url>`), since they belong to the previous account: Claude reads one before publishing to it again, and says so if the link will change.
  - It changes `handoff.json` only under `handoff.json.lock`, the folder lock the relay takes for its own changes, so sessions that hit a limit together, or start together after a switch, don't lose each other's entries.
  - It draws the `/account` row and handles `/account add <name>`. If Claude hasn't closed 90 seconds after the row's Switch or Sign in, the row goes back to normal and says to look at `relay.log`.
- **The relay** (`relay.sh`) does anything that closes Claude as a one-shot launchd job, so it survives Claude quitting. A command run by hand (`use`, `add`, `signin`, `restart`) queues that job and returns; the job's plist sets `ACCOUNT_SWITCHER_JOB`, which tells the relay to do the work itself. A job is never started over one that's running (that would kill it): the command is turned away instead, and the mod's out-of-usage trigger leaves its sessions to the job already under way. While the keep-alive holds the lock (it runs as a job of its own), the out-of-usage switch is started anyway and waits for it, up to 10 minutes, instead of being dropped; a command run by hand is turned away.
- **One lock for anything that moves a sign-in** (`switch.lock`: a switch, `use`, `add`/`signin`, `restart`, `remove`, the keep-alive). It holds its owner's pid. A live owner keeps it however long it runs (a sign-in can take over 15 minutes); a lock whose owner is gone, or whose pid now belongs to a process started after the lock was made (a reused pid), is taken over, by one process at a time (`switch.lock.takeover`).
- **A sign-in is never overwritten.** Every move takes `Cookies` and `Cookies-journal` together (a journal left beside another account's `Cookies` would be rolled into it), and a sign-in already where one is going goes to `backups/` first.
- **A run cut off half-way is put right.** A sign-in waiting for you has the current account's sign-in parked; a keep-alive has a parked sign-in in its throwaway profile (`keepalive-profile/account` says whose); a switch moving the sign-ins has written `swap.inflight` (`<from> <to>`, then each move just before it makes it, and `back` before it moves them back), since for a moment Claude holds the new account's `Cookies` while the app still reports the old one. Putting such a switch right undoes its moves, last first, so every file goes back where it was, whichever move it was cut off at; what Claude made in its folder if it was opened in the meantime goes to `backups/`. Killed by launchd (SIGTERM), each puts the sign-in back as it exits (a switch whose new account had already come up is left on it). Killed outright, the next locked command puts it back before doing anything else, and `relay.sh doctor` reports it until then.
- **Sessions cut off mid-turn are reopened.** Whatever the relay closes Claude for, the sessions mid-turn then (`busy/`) are listed in `handoff.json` as cut off, with the account they were on, and reopened on whichever account Claude comes back on.

An out-of-usage switch:
  1. Takes the lock, so only one switch runs at a time (waiting for the keep-alive if it holds it). A trigger from an account Claude has already left (several sessions hit the limit together, or you switched by hand meanwhile) only records the cooldown.
  2. Puts the spent account on cooldown until its reset time (from the usage window).
  3. Reads every account's usage from Anthropic where a login allows, and picks the next account after it in `accounts.json` that isn't cooling down, has a parked sign-in that hasn't run out, and has no window used up (5-hour or weekly, or the model limit that ran out) that hasn't reset since its last reading. If the usage figures can't be read, it picks without them (and logs it). The hand-off entries for this limit are stamped with that account.
  4. Checks the app's files and quits Claude. If Claude has downloaded an update, it installs as Claude quits; the relay waits (up to 3 minutes) for it to finish, so Claude opens on the new version instead of being replaced underneath later. If an update did install, the files are checked again; if they're not where the relay expects, Claude is opened again with nothing moved and the switch fails. Then it moves the sign-ins, links any new session folders, copies per-account settings across, fixes scratch paths, and opens Claude.
  5. Waits up to 45 seconds for the new account to come up; if it doesn't, puts the previous sign-in back and tries the next account that's ready, until one comes up or none is left.
  6. Reopens each handed-off session with `claude://resume?session=<id>`: those written before Claude was closed, meant for the account it's on now (or cut off mid-turn), within 15 minutes, the same ones the mod acts on.
  7. Checks the shared session list for sessions that went missing: a session file gone with no `deleted_<id>` marker from the app was lost, not deleted. Each is logged and notified once; `relay.sh doctor` lists them.

## Files

| In this repo | What it is |
| --- | --- |
| `relay.sh` | The switcher. Linked from `~/.claude/desktop-account-switcher/relay.sh`. |
| `mod/` | The Claude Code mod (hooks + the `/account` row). Linked from `~/.claude/desktop-account-switcher/mod`, which is the `desktop-account-switcher-local` plugin marketplace. |
| `accounts.example.json` | What `~/.claude/desktop-account-switcher/accounts.json` looks like (setup and `add` write it for you). |
| `tests/` | End-to-end tests (`tests/e2e.sh`) and the stand-ins they run against. |
| `docs/` | This page, research notes on the app's sign-in, every permutation of state and action checked ([permutations-2026-10-21.md](permutations-2026-10-21.md)), and the history of the earlier design. |

Live state, never in git, in `~/.claude/desktop-account-switcher/`:

| File | What it holds |
| --- | --- |
| `accounts.json` | Each account's `name`, `accountUuid`, `orgUuid`, and optionally `email` (shown by `status`). Order is the order accounts are tried. |
| `config.json` | `{ "armed": true }` turns automatic switching on (the row's toggle writes it). |
| `state.json` | Cooldowns (`accountUuid` → reset time), the last switches, and when usage was last read from Anthropic. |
| `usage.json` | Each account's last usage reading (`source`: `anthropic` or `session`) and when it was taken. |
| `seen-sessions.json` | The session ids in the shared list at the last check, to tell when one goes missing. |
| `park/<accountUuid>/` | The parked sign-in (`Cookies`, `Cookies-journal`) of each account not in use. |
| `handoff.json` | Sessions waiting to be reopened, each with the account it comes back on, and when the relay last closed Claude (`closedAt`). Changed only under `handoff.json.lock`. |
| `swap.inflight` | Held while a switch moves the sign-ins: from and to, and each move made. Left behind, the switch was cut off, and the next command puts it right. |
| `switch.lock/` | Held while a switch, sign-in, restart, remove or keep-alive runs: its `pid` and command. |
| `*.lock/` | Short locks: `handoff.json.lock`, `state.json.lock` and `usage.json.lock` around each change to that file (the mod takes them too), `cli.lock` while a terminal login moves. One older than 10 seconds is left over and removed. |
| `keepalive-profile/` | The keep-alive's throwaway profile folder; `account` names whose sign-in is in it while one runs. |
| `busy/` | Which sessions are mid-turn. |
| `relay.log` | Everything the relay and the mod did, in local time. |
| `backups/` | Copies taken before each change: session lists, preferences, session files whose paths were rewritten, removed accounts. |

## Testing

`tests/e2e.sh` runs `relay.sh` the way a person does, in a throwaway home folder. It runs against a stand-in Claude app (a process that shows in `ps` under the app's path, and "signs in" from a test Cookies file), and stand-ins for `open`, `launchctl`, the Keychain, notifications and the `claude` CLI. It covers setup, adding accounts, the shared session list, switching by hand and on a usage limit, every account out, a changed app layout, terminal logins, removing an account, a switch going back when the new sign-in doesn't come up, a second command while one runs, a sign-in killed while it waits (by launchd, and outright), a switch killed while it moves the sign-ins (by launchd, and outright), a limit switch skipping an account whose parked sign-in ran out or trying the next when one doesn't come up, a limit switch waiting for the keep-alive, a limit trigger from an account already left, sessions cut off mid-turn being reopened, the keep-alive skipping while the lock is held, names with quotes and `&`, and moving from the old launchd label. The mod's hooks run in `tests/fakes/mod-host.ts` (with `bun`), a stand-in for the Claude Code host: one session's process per event, with real files and the real relay; what the session would show goes to a log. That covers sessions hitting the limit together, being reopened and told why, being cut off mid-turn, and the mod's no-switch cases. A real `claude` session, with the mod, hits a usage limit against `tests/fakes/api.ts` (a stand-in for Anthropic's API that refuses every request as a used-up 5-hour window), and the switch and the reopen follow. `tests/sweep.sh`, in the same stand-in world, runs two parts with too many states to list in every one of them. In the first, a real switch is cut off at each of its moves of a sign-in file, through a stand-in `mv`: before or after the move, by SIGKILL or SIGTERM, with Claude opened from the Dock in the meantime or not. It covers a switch that works and one that goes back, with the journals and without. In the second, `relay.sh plan` runs for every combination of the other two accounts' sign-in, cooldown and last usage reading, with the limit that was hit. Each case is checked against a rule stated once in the script. `tests/host/sequences.test.ts`, run in Claude Code's own engine by the suite, takes every sequence of up to 4 of a session's events, time passing among them (4680), checks each step against a model of what the mod should do, and checks that this covers sequences of any length. `tests/host/live.sh` runs the mod in a real `claude -p` session (the real host and model), started as the app starts one, in a throwaway home folder: a turn marks its session busy and its end clears it, and a resumed session gets its carry-on message once. Nothing touches the real Claude, Keychain or launchd. `ACCOUNT_SWITCHER_APP` points the relay at the stand-in app; `ACCOUNT_SWITCHER_FAST` shortens its fixed waits.

When a new Claude Desktop version is out, try a switch by hand (`relay.sh use <name>`). If it works, add the version to `TESTED_VERSIONS`.
